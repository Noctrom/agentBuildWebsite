# V0.55 — Shared band component for grouped sections (2026-10-05)
**Agent:** dev-1
**Branch:** story/v0.55-section-band · **Status:** done

**What I did**
- Added `SectionBand` in `src/components/ui/`, exported from the `ui` index with `SectionBandProps`. It wraps its children in the same frosted band as `Section tone="surface"`.
- Both now use one recipe, `bandClass` in `ui/tone.ts` (`glass-edge border-y border-border` plus `glassClass.surface`). `Section` uses it for `tone="surface"`, and `SectionBand` uses it with `-my-px`.
- Kept V0.46's even spacing. `SectionBand` adds `-my-px` to cancel the 1px top and bottom border, so a gap across a band edge stays one `--spacing-section`.
- Behind the Scenes uses `<SectionBand>` in place of the `<div className={bandClass}>`. I removed the page's `bandClass` constant and its `ui/tone` import (the one swap the leader approved). The page now imports only from `components/ui` and `content`.
- Behind the Scenes and About (`Section tone="surface"`) are pixel-identical before and after at 375, 768 and 1280.

**How I did it**
- The shared recipe is a string constant next to `glassClass`, the same pattern `tone.ts` already uses. I didn't add a wrapper component inside `Section`, because Section's band sits on the `<section>` itself; a constant keeps Section's DOM unchanged.
- `SectionBand` renders a plain `<div>`. The `<section>`s inside it carry the landmarks and headings, as in V0.46.
- In the class attribute, the band classes come after `-my-px` instead of before it. Class order doesn't change Tailwind's CSS output, and the screenshot diff confirms it.

**Verification**
- `npm run build`: passes. `npm run lint`: passes, no warnings.
- Screenshot diff: I built `leader` (418a7db) before any change and the branch after it, then served both with `vite preview` on my own ports, 4761 and 4762. A Playwright (playwright-core) script took full-page screenshots of `/behind-the-scenes` and `/about` at 375, 768 and 1280 wide.
- To keep the animated scene out of the diff I did two things. Every context emulates `reducedMotion: 'reduce'`, and an injected style hides the background canvas (`canvas { visibility: hidden !important }`), so the glass blurs a fixed backdrop.
