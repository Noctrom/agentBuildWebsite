# V0.49 — Animation switch also controls UI motion (2026-10-05)
**Agent:** dev-1
**Branch:** story/v0.49-ui-motion-switch · **Status:** done

**What I did**
- Switch Off (or auto-paused): hover/focus transitions snap, CSS animations finish at once, and `motion-safe:` effects (the V0.38 nav-button grow) don't apply.
- Switch On: UI motion runs even with the OS reduce-motion setting on.
- No saved choice: UI motion follows the OS setting, live when the OS setting changes.
- Toggling the switch updates UI motion at once, in this tab and in other open tabs.
- No motion flash on load with a saved Off: an inline script in `index.html` sets the attribute before first paint. If storage throws, it falls back to the OS setting and the page still works.
- The global reduced-motion rule and the `motion-safe` / `motion-reduce` variants now key on the attribute. No component is left on the media query alone.

**How I did it**
- `motionPreference.ts`: new `syncMotionAttribute()` mirrors `getReducedMotion()` to `<html data-motion="reduce|full">`. It subscribes through the existing store `subscribe`, so the switch, auto-pause (`setMotionChoice('auto-paused')`), the `storage` event from other tabs and OS `matchMedia` changes all update it. It is called once in `src/main.tsx` before render.
- `index.html`: a tiny inline script in `<head>` with the same logic (storage key `motion-preference`, values on/off/auto-paused, then the media query), wrapped in try/catch. It repeats the key, so both places have a "keep in sync" comment. I kept it inline rather than importing the key, because it has to run before the module bundle.
- `index.css`: `@custom-variant motion-safe` / `motion-reduce` (Tailwind v4 overrides the built-ins) match `[data-motion=full|reduce]` on the root and its descendants. The global snap rule is now `[data-motion='reduce'] *` (plus `::before`/`::after` and the root itself). Fallback: if the attribute is missing (the inline script never ran), both the variants and the rule fall back to the OS media query on `:root:not([data-motion])`, so the old behaviour stays as a safety net. I checked the compiled CSS: `motion-safe:hover:scale-[1.06]` compiles to `:where([data-motion=full],[data-motion=full] *):hover` plus the media-query fallback.
- Comments in `Header.tsx` and `ui/tone.ts` updated to say reduced motion means the switch, else the OS.

Grep of `motion-safe:`, `motion-reduce:` and `prefers-reduced-motion` in `src/` (including dev-2's pages, content and scenes, read-only) and `index.html`:
- `src/components/layout/Header.tsx:20` `motion-safe:hover:scale-[1.06]`: now follows the attribute.
- `motion-reduce:`: no uses.
- `prefers-reduced-motion`: `styles/index.css` (now only the fallback when the attribute is missing), `motionPreference.ts` `REDUCED_MOTION_QUERY` and the `index.html` inline script (both read the OS setting as input). These are the intended exceptions.
- dev-2's `src/pages/`, `src/content/` and `src/scenes/`: no uses. Scenes get `reducedMotion` from the engine, which has followed the store since V0.41. Nothing to report.
- Transitions covered by the global rule: `ui/tone.ts` `glowClass`, the Header nav bubble and button, `AnimationToggle`, `Footer`, and the `AutoPauseNotice` close button.
