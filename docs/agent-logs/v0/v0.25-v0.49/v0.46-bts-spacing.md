# V0.46 — Behind the Scenes: one band, tighter even spacing (2026-10-05)
**Agent:** dev-2
**Branch:** story/v0.46-bts-spacing · **Status:** done

**What I did**
- "How work flows" and "Branches and reviews" now sit in one continuous frosted band, with no line between them.
- Every other section (title/intro, Why build it this way, The team, The stack, How the site works, See for yourself) is plain, with no band (`tone="surface"` removed).
- The gap from the last line of one section to the next heading is 64px everywhere (it was about 128px). That includes inside the band and across both band edges. Inside the band, there are 33px above the first heading and 33px below the last content (32px padding plus the 1px border).
- Headings and intros inside the band use the same Section markup as outside it, so they look the same: measured identical font size, weight, line height, colour, max width and left edge at all three widths.
- Only `BehindTheScenes.tsx` changed, so the other pages are untouched.
- All text on the plain sections passes AA over the live scene (numbers below).

**How I did it**
- Page-level classes only, with no change to `Section`. Each section gets half of `--spacing-section` above and half below (`pt-[calc(var(--spacing-section)/2)] pb-[...]`). Two halves meet at every boundary, so the gap is the same whether or not a band edge falls between them. The page's outer edges keep the full 64px: `pt` on the title and `pb` on the last section are left at `py-section`. I confirmed in the built CSS that `padding-top`/`padding-bottom` come after `.py-section{padding-block}`, so they override it (the same pattern as Home's `pt-0`).
- The band is a plain `<div>` around the two sections, using Section's own glass recipe (`glass-edge border-y border-border` + `glassClass.surface`). `-my-px` cancels the band's 1px borders, so gaps across a band edge measure exactly 64, not 65.
- `glassClass` is not exported from the `ui` barrel, so the page imports it from `components/ui/tone` directly.
- Inside the band, both diagrams use `tone="bg"` (the documented tone for content in a surface band). BranchDiagram used the default `surface` tone before because it was not in a band.
