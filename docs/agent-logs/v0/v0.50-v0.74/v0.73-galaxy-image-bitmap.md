# V0.73 — Contact galaxy uploads stars with createImageBitmap (2026-10-17)
**Agent:** dev-2
**Branch:** story/v0.73-galaxy-image-bitmap · **Status:** done

**What I did**
- The Contact galaxy's moving stars are now sent to the GPU with `createImageBitmap` while animating. On the real GPU the page went from 25–26 fps (every third frame over 35 ms) to a steady 60 fps at 1280. Nowhere did it measure worse.
- Still frames (reduced motion, Animation off, first frame after a resize) keep the synchronous `putImageData` path. They are pixel-identical to before.
- Bitmaps are closed when replaced, on resize and on dispose. At most one bitmap is live, and none after leaving Contact.
- Reworded the source comments in `galaxyPalette.ts` and `galaxyBand.ts` to say "Chris's Milky Way reference photo". Nothing in `src/` mentions `night-sky-Milky-Way-Galaxy.webp` any more.
- Looks the same at 375 and 1280 (side-by-side images below).

**How I did it**
- `publish(sync)` in `galaxyStars.ts` fills the `ImageData` as before. After that:
  - **Sync** (still frame, first frame, or no `createImageBitmap`): `putImageData` into the buffer canvas, as before. It also drops any bitmap.
  - **Async:** `createImageBitmap(image)`. Each publish gets an id. When the promise resolves, the new bitmap replaces the shown one and the old one is `close()`d. A bitmap that resolves after a newer frame was shown, or after a resize or dispose, is closed right away.
  - Only one upload is in flight at a time. If the previous one hasn't landed, that refill is skipped rather than queued (the leak run shows this never happened at 60 fps: 20 bitmaps a second).
  - Each frame draws `bitmap ?? canvas`.
- `createImageBitmap(ImageData)` copies the pixels when it is called, so reusing `image` for the next refill is safe.
- Dirty-rect `putImageData`: I considered it but didn't build it. The bitmap path already holds 60 fps with 0% slow frames everywhere I could measure, so there was nothing left for it to win.
- Real-GPU path in headless Chromium on WSL: `--enable-gpu --ignore-gpu-blocklist` with `GALLIUM_DRIVER=d3d12` and `LD_LIBRARY_PATH=/usr/lib/wsl/lib`. WebGL then reports "D3D12 (AMD Radeon RX 7800 XT)". Without the env it falls back to llvmpipe.
- Under software raster at 4× the V0.42 auto-pause kicked in for both builds, which made the fps numbers meaningless. I re-ran those with the Animation choice set to "on" (`motion-preference` = `on`), which turns off the auto-pause watch.
