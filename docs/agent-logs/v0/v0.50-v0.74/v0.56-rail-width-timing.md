# V0.56 — Rail width ready before scenes draw (2026-10-05)
**Agent:** dev-1
**Branch:** story/v0.56-rail-width-timing · **Status:** done

**What I did**
- With animation off, client-side navigation into Behind the Scenes now centres the black hole in the visible area beside the rail at 1024, 1280 and 1440, from Home and from Projects. It used to sit 37.5–44.5px left of centre.
- The rail is unchanged: same V0.47 widths per page, and `--rail-width` is still written once per navigation. No sampled frame shows main's padding lagging behind the rail, so there is no layout shift or flicker.
- Direct loads, resizes (including below lg, where the rail width is 0) and animation-on behave as before.

**How I did it**
- Cause: `--rail-width` was only updated by the Header's ResizeObserver. Its callback runs after layout, and React runs a click navigation's passive effects before that. `SpaceBackground` calls `engine.setScene` in a passive effect, and with animation off the engine draws its only frame right then, using the old width (98px on Home, 112px on Projects instead of 187px). Nothing redraws after that.
- Fix (Header side only, as dev-2 suggested): a second `useLayoutEffect` keyed on `pathname` that publishes the width. Layout effects run before any passive effect, and by then the NavLinks have committed the new current page, so the measured width is already the new one. I moved the measuring into a module function `publishRailWidth`, which skips the write when the value hasn't changed. That way the ResizeObserver callback that follows doesn't set the same value again. The ResizeObserver stays for breakpoint and font changes.
- I left `src/scenes/` alone: `followRail()` already picks up the new value on every drawn frame.
