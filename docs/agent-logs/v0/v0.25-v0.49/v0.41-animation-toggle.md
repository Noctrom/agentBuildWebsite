# V0.41 — Animation on/off control in the footer (2026-10-05)
**Agent:** dev-1
**Branch:** story/v0.41-animation-toggle · **Status:** done

**What I did**
- Added a small "Animation" switch (track, knob and an On/Off word) to the footer on every page. It sits between the copyright and the social links: stacked and centred at 375px, in the middle of the row from `sm`.
- Off makes every scene still, the same path as OS reduced motion (the engine's existing `setReducedMotion`). On resumes animation.
- A saved choice overrides the OS in both directions: with OS reduce on, "on" animates; with OS reduce off, "off" stops the scenes.
- The choice is saved in localStorage (`motion-preference`), so it survives page changes, reloads and new visits on that browser. Other open tabs update live too.
- With no saved choice the site follows the OS setting as before, including live OS changes.
- It's a native `<button role="switch" aria-checked>` named "Animation". It works with Tab, Space and Enter, shows the focus ring and glow the footer links use, and is 24px tall.

**How I did it**
- New `src/components/layout/motionPreference.ts` is the single source of truth. It's a small external store with `MotionChoice = 'on' | 'off' | 'auto-paused'`, or `null` for "follow the OS". It provides `getMotionChoice`, `setMotionChoice(choice | null)`, `isExplicitMotionChoice`, `getReducedMotion` and the hooks `useReducedMotion()` / `useMotionChoice()`. It sends updates when the OS media query changes, when `setMotionChoice` is called and on the `storage` event from other tabs.
- V0.42 hooks: `setMotionChoice('auto-paused')` stores a distinct state that counts as off and shows as off in the footer. `isExplicitMotionChoice()` tells whether the visitor chose (`on`/`off`) or not (`auto-paused`/`null`). Clicking the switch while auto-paused saves an explicit `on`.
- Every localStorage read and write is wrapped in try/catch. If storage throws, the choice stays in memory for that page session. Unknown stored values are ignored (treated as unset).
- `SpaceBackground` now calls `useReducedMotion()` from the store instead of its own `matchMedia` code. I didn't need to change the engine or the scenes: the engine already gets the flag from `SpaceBackground`.
- I chose `role="switch"` over `aria-pressed` because screen readers announce it as "Animation, switch, on/off". The visible On/Off word is `aria-hidden`, so the accessible name stays "Animation". Colours are existing AA tokens: the label is muted text, which turns accent on hover. Off is a muted outline with a muted knob, and on is an accent track with an accent-fg knob (8.73:1).
- Out of scope, left on the OS setting only: the global `prefers-reduced-motion` CSS rule in `index.css` and `motion-safe:` utilities (the V0.38 bubble grow). I noted this in the CSS comment.

**Follow-ups**
- CSS motion (the global reduced-motion rule and `motion-safe:` such as the V0.38 bubble grow) still follows only the OS. Covering it is fairly simple but not trivial. The store would set `data-motion` on `<html>`, the media rule would become `:root[data-motion="reduce"] *`, and `motion-safe`/`motion-reduce` would be redefined with `@custom-variant`. It would also need a tiny inline script in `index.html` to avoid a flash on load. Whether a "background animation" switch should also control UI transitions is a product call for Chris.
