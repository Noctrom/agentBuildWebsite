**How I did it**
- **Cause:** the clouds were drawn with `createRadialGradient` into a quarter-size bitmap, which is then stretched to the screen. Chrome dithers gradients with a fixed ordered pattern, and the stretch turned that pattern into a visible checker. A quick test at scale 0.5 only made the checker finer, so the pattern itself had to go.
- **Bake in code** (`bakeClouds`). The same glows, in the same order and with the same random numbers, so the layout is identical:
  - Each glow uses the old gradient stops: full at the centre, 35% halfway out, 0 at the edge.
  - Glows add up premultiplied like the old `'lighter'` blending, clamped at 255. Clamping once at the end gives the same result as clamping after each glow, because glows only add.
  - The dust holes then remove a share of the cloud, like the old `'destination-out'`.
  - The result goes to 8 bits with random dither (±0.5 of a step) applied to the premultiplied values. The colour written is the one whose premultiplied value lands on the dithered number, so the canvas's own premultiply doesn't bring the steps back.
  - The dither table is seeded and made once.
- **Speed:** a plain version took about 110 ms at 1280 with 4× throttle (long tasks). What brought it down:
  - Each glow visits only its own disc, row by row.
  - The texel loops are small per-row functions (`glowRow`, `holeRow`, `outputRow`), so V8 optimizes them quickly. The same trick as `eachRow` in `nebula.ts`.
  - Falloff lookup tables indexed by squared distance remove the square root.
  - The output pass has no division or `Math.round`: it uses a reciprocal table, and `Uint8ClampedArray` rounds and clamps by itself.
  - The bitmap scale went from 0.25 to 0.125. That is a quarter of the texels, and with random dither it still upscales smoothly. The zooms show no blockiness, and the normal view is within 2/255.
- **Timing:** each layer is baked by `setTimeout(0)` in its own task right after setup (`scheduleBakes`).
  - If a frame comes first (reduced motion, a hidden tab, a resize), `draw` bakes whatever is missing, so every frame shows both layers.
  - `build` and `dispose` cancel pending bakes.
  - Before this, adding the bake to setup or to the first frame created a new 55–115 ms long task at 1280 with 4× throttle.
- **Why the before bake looked free:** Chrome records canvas gradient draws and rasterizes them at the first `drawImage`. So the old cost sat in the first frame, not in setup. My bake harness times setup plus the first draw for a fair comparison.
- **Out of scope:** no change to `backgroundEngine.ts` or to any other scene file. All six scenes get the fix through `createStarfield`.
